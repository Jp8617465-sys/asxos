`proposed_target: approved-lessons.md`

#### L9 — Reversible work is inside arbi's standing authority: scope it, and open the draft PR, without asking
`proposed_target: approved-lessons.md` — folds `L-cand-2` **and** `L-cand-3` of
`working/2026-07-12-scope-reversible-without-asking.md` into one two-beat lesson.
When arbi has found the structural cause behind a complaint and the next step is a **reversible**
artifact (proposal / design / docs / scoped plan): (a) **produce it immediately** — do not end
with "want me to scope this?"; scoping is itself reversible and is the operating controller's

durable stopping point; branch-only state is itself the visibility failure the work often exists
to fix. Stop and ask James **only** when the *next* step crosses a reserved boundary: capital,
broker execution, migration/DB write, deploy, merge, secret, Render/infra mutation,
governed-thesis write, policy/conviction change, gate flip, or a red safety-hook denial.
**Do-not-overgeneralise:** this is NOT "act without asking" — the boundary set is unchanged and
hard.
*Evidence:* two direct James corrections, 2026-07-12 (`working/2026-07-12-...md:22-27,64-68`);
decision-log `pr1-2026-07-13` captured them as L-cand-2/L-cand-3 "captured, not adopted."

#### L10 — PR transaction discipline; log every slip honestly and gate continuation on verified-safe state
`proposed_target: approved-lessons.md` — folds `L-cand-4` + `L-cand-5` of
`working/2026-07-14-pr-transaction-discipline.md`.
On any branch that backs a PR: (1) chain **commit && push && PR-state read** as one transaction —
never let a push run after a failed commit (independent statements are how a bare-base
force-push happens); (2) avoid force-pushing a reviewed branch unless the mission explicitly
requires reconstruction; (3) after any force-push/rebase, immediately verify PR head/base/
open-closed/diff-count against expectation via **live reads, not memory**; (4) if GitHub
auto-closes a PR on head==base, reopen and report immediately; (5) **never smooth over a slip** —
log it in the ledger and the session report even when fully recovered; (6) prefer fresh branches
for unrelated work. On any discovered slip: stop new work, verify the affected refs against
expectation, log it, continue **only** if state is verified safe. Honest logging is what keeps
autonomy expandable.
*Evidence:* the #29 auto-close incident, `working/2026-07-14-...md:9-18`; James's verdict
("net-positive; the lesson is stronger transaction discipline, not stop autonomy"). Governor
instruction: encode both verbatim into the 12h `/goal` recipe (`arbi-goal-recipes.md`).

#### L11 — A green suite, a mocked connection, or hand-written SQL is not proof against the live constraint
`proposed_target: approved-lessons.md` — **extends approved L7** (which is the same lesson for
governance-trigger statement ORDER) to the constraint/writer side. Do not re-file as unrelated.
Mocked DB connections don't enforce constraints or triggers; a 1264-passing suite proves nothing
about what the DB rejects. Before considering a DB-touching change done, **replay the exact
emitted statement against the real schema** (a rolled-back txn is fine). For an additive
`NOT NULL`-no-default column: update **every INSERT writer** (not just readers) in the same
change that applies the migration, or ship the column nullable + backfill + writers first, THEN
set `NOT NULL`. Never paper over it with a `DEFAULT` if the default would silently misclassify a
future write (the exact pollution vector the column exists to close).
*Evidence:* `working/2026-07-11-etf-phase1-build.md:14-45` — 0037 applied to prod while
