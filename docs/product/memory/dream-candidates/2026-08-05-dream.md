## Durable lessons (candidates)

### L-cand-05.1 — A test that claims regression coverage must be shown to FAIL without the fix

**Not a restatement of L11 — a control for it.** Six guards were mutation-tested this session
by reintroducing each bug and checking whether the named test failed. **Five were genuine; one
was hollow**, and a separate pre-existing test proved hollow too. Neither was detectable by
reading; both were detectable in seconds by running.

The concrete rule: any test whose name or docstring contains *regression*, *pins*, or *guard*
must have been observed failing against the un-fixed code before that claim may be written.
Comment the observation, not the intention.

Evidence: `c2a7f76` (mutation results table; CWE-117 scrub had zero coverage despite an
eight-line comment asserting the property); `002b6c9` (the request-side fix shipped with zero
coverage — reverting `eodhd_symbol()` left all 52 news tests green).

`proposed_target`: `approved-lessons.md`, **and** a mechanical gate — see *Contradictions /
decisions for James* #1. A fourth prose copy without the gate is predicted to fail.

### L-cand-05.2 — Status is not evidence of work; assert on the artifact

A ship condition, a runtime freshness gate, and a deadman all keyed off
`job_runs.status='success'`. One defect cleared all three, and a surface was marked SHIPPED
while rendering nothing for a month. Two checks reading the same field are one check.

The rule, now also written into `dark-launch-exit-plan.md` as a standing rule: a gate must
require `rows_written > 0`, or join the table the job populates (as the portfolio gate joins
`rebalance_runs`). Corollary: **a job's success predicate must be able to return False** —
`is_ok=lambda r: isinstance(r, int) and r >= 0` accepts every int, so 22 consecutive
fully-failing runs each scored 100% healthy.

Evidence: `deea76a`; `d549688`; `asxos/brief/compose.py::_news_ingest_fresh`.

`proposed_target`: `approved-lessons.md` (generalises beyond this repo's news path).

### L-cand-05.3 — Low-volume pipelines fail silently; high-volume ones announce themselves

Every silently-broken feed in this window is low-volume (news, sentiment, iron ore, the AU 10y,
factor scores). `prices` — 733,719 rows, ~48k/month — ran green through an 11-day idle window
and would have screamed if it hadn't. This is not fragility, it is **unobservability at low
volume**: a job writing 0–10 rows a day is indistinguishable from a quiet day, so it needs an
explicit contract (expected range, expected change cadence) that a high-volume job gets for
free from the sheer visibility of its output.

Evidence: report §1/§7 (`a255537`); `iron_ore_62fe` 0-for-24; AU 10y frozen 14 sessions;
`rs_factor_scores` 11 symbols all 0.000.

`proposed_target`: `project-facts.md` (a property of this system's data plane), with the
contract-test proposal going to `docs/next-session-backlog.md`.

### L-cand-05.4 — Parallel mutation/refactor agents need worktree isolation

Six mutation agents shared one worktree and contaminated each other's measurements: two wrote
backups to the same filename, two recorded a mid-mutation snapshot as the "pristine" hash, and
one produced a **false escalation** about a branch defect that did not exist. The per-mutation
isolated cycles were authoritative and all agreed; the shared-tree observations were not.

Rule: any fan-out whose agents mutate files must use `isolation: 'worktree'` or serialise, and
must use unique backup filenames. Note also that a concurrent commit landed mid-run — the
commit was clean only because staging happened before the mutation and `git commit` uses the
index.

Evidence: `c2a7f76` commit body (process note).

`proposed_target`: `approved-lessons.md`.
