Live finding  the regime label is now visibly contradicted by the tape

The market closed at 9,227.80 on 5 August — a new record high (intraday 9,230), up 0.9% on the day. Our system's newest row is 9,145.80 from 4 August, and its regime classifier has read risk_off_orderly on every one of the last 24 days.

That label was never a risk assessment — it is breadth_200_thin firing alone, with two of the other four rules structurally unable to fire at all (§7). A single-rule label that says "risk-off" into an all-time high is not a market call; it is a threshold with a name attached. The underlying observation is still true and still useful — 73% of the market is below its 200-day average — but "risk_off_orderly" is the wrong label for it, and anything downstream consuming that string is being misled.

Finding 01 — before you read the rest

The news feed is empty, and it reports success every day

Critical  ingest_news — 22 consecutive green runs, 0 rows written

holding_news contains zero rows. Every ingest_news run from 2026-07-06 to 2026-08-04 recorded status='success' with rows_written = 0. There is no article-level news in this system for the past month, the past week, or at all.

The cause is the success predicate in jobs/ingest_news.py:156: is_ok=lambda r: isinstance(r, int) and r >= 0. Its companion _fetch_and_upsert() catches every exception and return 0 (line 70). Because 0 >= 0 is true, a run in which every single symbol fails scores 100% healthy and sails past the threshold=0.75 gate in assert_partial_success. The job cannot fail. This is the failure mode CLAUDE.md non-negotiable #10 exists to prevent.

The same fabricated field defeats a second, independent guard. compose.py documents three-layer gating on the news section, and layer 3 is a freshness check — _news_ingest_fresh() (compose.py:514-525) queries job_runs WHERE job_name='ingest_news' AND status='success'. That is the identical field the bug forges. So the ship condition and the runtime freshness gate are not two checks; they are the same check twice, and one bug clears both. Defence in depth that shares a single point of failure isn't depth.

Consequence  the news brief was signed off on this green

docs/product/dark-launch-exit-plan.md ships surface #2 on ship condition (a): “job_runs shows ingest_news status='success' every scheduled business day for 3+ weeks … zero failures.” That is precisely the signal the bug fabricates. The verification checked job status; it never checked row count.

This is not pending — it is already live. ASXOS_NEWS_BRIEF_ENABLED = "1" is on origin/main (render.yaml:414), and compose_brief has run successfully 22 times in the last 30 days. compose.py:507 gates the section on that flag alone, then calls _holding_news() against an empty table. The daily brief has been shipping an empty news section every day since the redeploy — a surface marked SHIPPED, rendering nothing.

Two related gaps, for completeness. signal_sentiment is also empty — but that is expected: it aggregates from holding_news, which is empty, and EODHD /sentiments has no ASX coverage on the current plan tier (documented REV-K pivot, 2026-05-24). rs_factor_scores covers only 11 symbols with every factor scoring 0.000, so no factor lens is available; it is excluded from this report rather than reported as noise.

In fairness the document flags its own limit in the header it adds: “Last verified: 2026-07-24 for programme precedence; individual legacy-surface facts still require live refresh.” That disclaimer is honest and it is exactly the refresh this report performs. On priority. The dossier's programme raises the stakes on ingest_news rather than lowering them. Retiring Model A while the news feed silently writes zero rows narrows the system to one working input. Fix #1 gets more load-bearing under this programme, not less.

The concern worth having about a 155-doc PR is its 2 code files: if scripts/validate_investment_program.py asserted on the exit plan's current text, merging would convert a wrong ship verdict from stale prose into a green test defending it.
