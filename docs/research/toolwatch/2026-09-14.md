## ADOPT

### 1. Bump the pinned `claude-code-action` SHA + add `--permission-prompts none` to all four agent lanes

**What changed.** All four of this repo's `claude-code-action` workflows are pinned to the exact
same commit, `a874e9ecd7bb36efdad65429c6b35815f5a08f10` (comment `# v1`) —
`weekly-toolwatch.yml:61`, `nightly-triage.yml:88`, `claude-execute.yml:117`,
`backlog-roll.yml:156`. I checked that commit directly against the `claude-code-action` repo's
history (`gh api repos/anthropics/claude-code-action/commits/...`): it is dated
**2026-08-28T18:20:42Z** and its own commit message is `chore: bump Claude Code to 2.1.251 and
Agent SDK to 0.3.251`. The bundled CLI is 2.1.251. The current tip is tag `v1.0.223`
(commit `9cdae7f0d995e3ba7c33f226087fdf82a59cd520`, published 2026-09-12T19:47:51Z), bundling
Claude Code **2.1.270** — 19 CLI versions ahead. Two of the released versions in that gap are
concrete, repo-relevant capabilities our pin does not yet have:

- **Claude Code 2.1.257 (2026-09-01, `code.claude.com/docs/en/changelog`):** *"Added a
  Containment Escape rule to auto mode so cloud metadata-credential fetches, egress evasion, and
  cross-tenant reach are no longer auto-approved unless your environment marks them expected."*
  All four lanes run `--permission-mode auto`. This is a harness-level guard against exactly the
  outbound/credential-fetch shape `security-perf-mission-loop.md` §8's weakening tripwire and §9's
  "Open P1 — write token exposed to untrusted-content agent" both worry about — it does not close
  P1 (the residual is the write token itself, not just metadata-endpoint reach), but it narrows
  one concrete exploitation path for an agent that reads untrusted PR/issue/changelog text while
  holding `ARBI_GITHUB_TOKEN`.
- **Claude Code 2.1.259 (2026-09-02, same source):** *"Added `--permission-prompts none` for
  unattended headless hosts: anything that would prompt is denied automatically while the active
  permission mode (including auto mode) keeps deciding."* Confirmed via WebSearch
  (`docs.claude.com/en/docs/claude-code/headless`, cross-checked, not taken on the search
  summary alone) that this is **not** `--dangerously-skip-permissions` — auto mode still
  classifies, the Containment Escape rule above still applies, and Claude is explicitly told
  "nobody can approve this, don't retry" instead of retrying a blocked action until the turn
  budget runs out. `claude-execute.yml:94-95` already documents today's actual fallback
  correctly ("every unlisted action is denied with no prompt and the run looks successful having
  done nothing") — the other three lanes' comments are vaguer ("blocked actions silently do not
  happen"). The flag makes that behaviour an explicit, documented contract instead of an inferred
  side effect of headless + auto mode, and it stops a would-prompt action from burning turns via
  retries against `--max-turns 60/80/80-or-100` budgets.

**Repo surface:** `.github/workflows/weekly-toolwatch.yml`, `nightly-triage.yml`,
`claude-execute.yml`, `backlog-roll.yml` — the `uses: anthropics/claude-code-action@...` line and
the `claude_args:` block in each.

**Diff sketch** (same two edits, repeated in all four files):

```diff
-        uses: anthropics/claude-code-action@a874e9ecd7bb36efdad65429c6b35815f5a08f10  # v1
+        uses: anthropics/claude-code-action@9cdae7f0d995e3ba7c33f226087fdf82a59cd520  # v1.0.223, bundles Claude Code 2.1.270 (2026-09-12)
```

```diff
           claude_args: |
             --max-turns NN
             --permission-mode auto
+            --permission-prompts none
             --mcp-config .github/runner/mcp.json
```

(`NN` is each lane's existing turn budget — 60/80/80/100 — unchanged.)

**Why it beats what we have.** Today, whether an unanswerable permission request is denied,
hangs, or gets retried until the turn budget is exhausted is an inferred property of "headless +
`--permission-mode auto`, no TTY" — accurate per `claude-execute.yml`'s own comment, but nowhere
enforced as a contract, and the other three lanes describe it more vaguely. `--permission-prompts
none` makes it a named, versioned flag with a citable behaviour spec, and its "don't retry"
instruction is a direct mitigation for turn-budget burn that none of these lanes currently have
any other defense against. The Containment Escape rule is pure upside at zero configuration cost
— it ships with the version bump alone.

**§8 weakening-tripwire check (required before calling this a clean win):** this change denies
strictly more (Containment Escape rule) and converts an implicit deny into an explicit one
(`--permission-prompts none`) — it does not remove a guard, broaden an allowlist, disable TLS, add
an outbound call, or read process env. It passes the tripwire; I am not required to hedge it, but
I checked.

**Risk of adopting.** This is a 19-release jump, not a single-fix bump — one behaviour change in
the gap is worth naming honestly: 2.1.267 changed task-tracking tools (`TaskCreate`/`TodoWrite`)
to be "offered only on Claude 3.x and specific Opus/Sonnet/Haiku versions," which could in
principle affect tool availability depending on which model each lane's OAuth token resolves to —
I did not verify which side of that gate this repo's default model falls on. The mitigating
factor: none of these four lanes merge without `full-check` passing on the PR they open (they are
draft/ready-PR generators, not direct-to-`main` writers), so a behavioural regression from the
bump would surface as a failing check or a reviewable diff, not a silent capital or write action.
Per `AGENTS.md` §6, this is an **Amber** shape (`.github/workflows/**` edit) — reversal cost is
low: one `git revert` restores the old pin and flags with no data loss, since these are stateless
CI config lines with no schedule armed yet (all four lanes are still `workflow_dispatch`-only per
`security-perf-mission-loop.md` §10-A gate 7).
